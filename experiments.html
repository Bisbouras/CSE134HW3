HTML experiments

A workbench page for elements that don't belong on the portfolio itself yet. Each section explains what the element is for and how this site will use it later.

<template>

A <template> holds markup that the browser parses but never renders. Below is the blueprint for a project card in the Work section of the home page. Nothing appears here on purpose: in a later homework, a few lines of JavaScript will clone it once per project instead of me copying the same article markup by hand.

<audio> and <source>

A placeholder footstep cue for KILLSTREAK: two low thumps and a soft ping, synthesised as a stand-in until real sound is wired into the game. Two <source> elements let the browser pick the first format it supports: Ogg Opus, which is smaller, then MP3 as a universal fallback.

<video> and <source>

A short silent sequence of my volumetric path tracing renders, from an empty Cornell box to the final light-shaft scene. It offers WebM (VP9) first and MP4 (H.264) as a fallback, has a poster frame so nothing downloads until someone presses play, and a text track describing each step.

<canvas>

Canvas is a bitmap you draw on with JavaScript. This one draws a KILLSTREAK-style vision cone: the player bottom left, their cone of sight, and an opponent who is visible because they are inside it.

A top-down drawing of a blue player in the lower left with a pale cone of vision stretching to the right, and a grey opponent standing inside the cone.

Custom elements

<project-facts>

A semantic wrapper for the key facts about a project (role, engine, dates, status), used at the top of the KILLSTREAK and volumetric path tracing pages. It contains a description list and has a small amount of CSS scoped only to itself that lays the terms and values out as a two-column grid. No JavaScript.

<hello-world>

When this element is on a page, it prints Hello World! to the browser console and changes nothing in the DOM. There is one on this page and one on the home page; open the developer console to see the message.

Extra credit: MathML

Einstein's mass-energy equivalence, written in MathML rather than as an image:

E = m c 2

Why couldn't developers use MathML until recently?

MathML has been part of the HTML specification for years, but a standard is only usable once every major browser renders it. Firefox has supported MathML since its earliest versions, and Safari has fully supported it since Safari 10. Chrome briefly turned it on in Chrome 24, then removed it in 2013 because the implementation was unstable, and Chrome-based browsers (Chrome, Edge, Opera, Samsung Internet) together hold most of the market. For roughly a decade, a page that used MathML showed broken, unformatted text to most visitors, so developers used images or JavaScript libraries such as MathJax instead.

That changed with Chrome 109 in January 2023, which shipped MathML Core, a smaller, precisely specified subset of MathML implemented by Igalia (Chrome 97 to 108 had it, but only behind a flag). Edge followed in the same version. caniuse.com now shows MathML working for about 96% of users worldwide, so it can finally be used directly.
